# Git Commit (Conventional Commits)

## Формат

```
type(scope): описание

body (опционально, если нужно объяснить «почему»)
```

- `type` — один из: `feat`, `fix`, `chore`, `docs`, `refactor`, `test`, `build`, `ci`, `style`, `perf`
- `scope` — ОДНО слово: что именно правится (i18n, tts, fsd, gitignore, pdf, modal, ui, deps...)
- `описание` — повелительное наклонение, кратко и конкретно, БЕЗ точки в конце
- Тикетов Jira у нас нет — поле не заполняем

## Правила

1. Сначала `git status` + `git diff --stat`: коммитим ТОЛЬКО запрошенное, никаких лишних файлов.
2. Если есть нежелательные файлы — `git add` выборочно, а не `git add -A`.
3. `git commit` без `-m` с несколькими строками: для однострочных — один `-m`, для многострочных — несколько `-m`.
4. **НИКОГДА не запускать `git push`** — пользователь пушит сам или явно попросит.
5. Заголовок коммита ≤ 72 символа.
6. Один коммит = одна логическая единица изменений. Если правок несколько разных типов — делаем несколько коммитов.
7. Не использовать `--amend` и `--force` без явного запроса.

## Примеры

```bash
git commit -m "feat(tts): голосовое приветствие на трёх языках"
git commit -m "refactor(ui): стрелочные компоненты и раздельные import type"
git commit -m "fix(contacts): телефон только для отображения, без ссылки tel:"
git commit -m "chore(gitignore): исключить todo-файлы из репозитория"
git commit -m "test(i18n): parity-проверка всех локалей ru/en/de"
```

## Большой коммит — structure

Если коммит большой, после заголовка пустая строка и body:

```bash
git commit -m "feat(demo): RTK Query форма отклика и GitHub-репозитории" \
  -m "Форма отклика: mutation на jsonplaceholder с состояниями loading/success/error и валидацией. Репозитории: query к api.github.com с кэшем и retry."
```

## Проверка перед коммитом

Прогони `npm run check` перед коммитом (lint + тесты + build). Если падает — сначала почини, потом коммить.
